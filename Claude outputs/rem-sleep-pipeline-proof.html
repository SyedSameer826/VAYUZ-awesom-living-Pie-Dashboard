1
Pi reads sleep stage byte from 0x4E frames glk_bridge.py

The GLK bed sensor sends sleep stage data in frames with command byte 0x4E. The Pi bridge registers this command, logs it, and forwards the raw frame to the backend.

# glk_protocol.py — command constants CMD_LOGIN = 0x03 CMD_TIME_SYNC = 0x02 CMD_DEVICE_INFO = 0x04 CMD_REALTIME = 0x0E CMD_SLEEP_STAGE = 0x4E CMD_EMERGENCY = 0x0D
# glk_bridge.py — command dispatch in handle_client() CMD_NAMES = {CMD_LOGIN: "LOGIN", CMD_TIME_SYNC: "TIME_SYNC", CMD_DEVICE_INFO: "DEVICE_INFO", CMD_REALTIME: "REALTIME", CMD_SLEEP_STAGE: "SLEEP_STAGE", CMD_EMERGENCY: "EMERGENCY"} # Status codes from 0x0E realtime frames STATUS_MAP = {0: "initializing", 1: "in_bed", 2: "apnea_suspected", 3: "snoring", 4: "out_of_bed", 5: "life_abnormality", 6: "light_sleep"}
# glk_bridge.py — 0x4E frame handler elif cmd == CMD_SLEEP_STAGE: log.info(" Sleep stage frame (%d bytes)", len(raw)) asyncio.get_event_loop().run_in_executor( None, forward_to_backend, sn, {"type": "sleep_stage", "raw_hex": raw.hex()})
The bridge forwards the raw 0x4E hex frame to the backend via POST /api/glk/vitals (local) and POST /api/health (remote EC2). Both receive the same payload with type: "sleep_stage".
2
Backend stores it in the glk_sleep_stage field health_logs.js

The backend parses incoming 0x4E frames, extracts vitals and sleep stage, and persists them in MongoDB with a dedicated glk_sleep_stage field.

// health_logs.js — raw frame parser const parse_glk_raw_frame = (raw_hex) => { const buf = Buffer.from(raw_hex, 'hex'); const payload = buf.slice(5, buf.length - 1); if (payload.length >= 11 && payload[0] === 0x6a) { const status_code = payload[6]; return { heart_rate: payload[4], respiration_rate: payload[5], status: glk_status_map[status_code], in_bed: glk_in_bed_statuses.has(status_code), battery_level: payload[7], body_movement: payload[10], }; } };
// health_logs.js — v24 pre-parsed sleep stage handler if (raw_data.type === 'sleep_stage' && (raw_data.sleep_stage != null || raw_data.sleep_stage_code != null)) { console.log( `[GLK_ORGANIC_DATA] serial=${serial} source=SLEEP_STAGE_PARSED` + ` stage=${raw_data.sleep_stage}` + ` HR=${raw_data.heart_rate} RR=${raw_data.respiration_rate}` ); return build_emfit_record({ serialnumber: serial, heart_rate: raw_data.heart_rate, respiration_rate: raw_data.respiration_rate, glk_sleep_stage: raw_data.sleep_stage, data_type: 'sleep_stage', }); }
// MongoDB schema — emfit_logs model glk_sleep_stage: { type: String, // "light" | "deep" | "rem" | "awake" default: null, }, data_type: { type: String, // "sleep_stage" | "emergency" | null (realtime) default: null, }
Two ingestion paths exist: the v24 bridge sends pre-parsed fields (sleep_stage already decoded), while the legacy path receives raw_hex and the backend parses it with parse_glk_raw_frame(). Both paths write glk_sleep_stage to the same MongoDB collection.
3
Dashboard calculates duration per stage glk_bedstate_service.js + dashboard_service.js

When a sleep session ends, glk_bedstate_service.js queries all logs for that session and tallies each stage's duration. The dashboard API also builds a stage timeline for the graph.

// glk_bedstate_service.js — session close: stage duration calculation const session_logs = await emfit_log_model .find({ serialnumber: serial, createdAt: { $gte: new Date(onset), $lte: new Date(now) }, }) .select('heart_rate respiration_rate glk_sleep_stage') .lean(); // Stage breakdown: each log ~ 30s interval const stage_counts = { light: 0, deep: 0, rem: 0, awake: 0 }; session_logs.forEach((l) => { const s = l.glk_sleep_stage; if (s && stage_counts.hasOwnProperty(s)) stage_counts[s]++; }); const est_interval_s = 30; const stages = { light_min: Math.round((stage_counts.light * est_interval_s) / 60), deep_min: Math.round((stage_counts.deep * est_interval_s) / 60), rem_min: Math.round((stage_counts.rem * est_interval_s) / 60), awake_min: Math.round((stage_counts.awake * est_interval_s) / 60), };
// dashboard_service.js — sleep stage timeline for the graph const build_stage_timeline = (readings, format_time) => { const detailed = readings.filter((r) => r.source === 'glk'); const source = detailed.length ? detailed : readings; const stage_of = (r) => { if (r.stage) return r.stage; // "light" | "deep" | "rem" | "awake" if (r.source === 'glk') return 'awake'; return r.sleep_stage ? 'sleep' : 'awake'; }; // Builds time-ordered intervals: [{start, end, stage}, ...] };
// dashboard_service.js — API response includes the timeline return { sleep_start, wake_time, last_night_sleep: { duration_hrs, avg_sleep_score_pct, intervals }, heart_rate: { avg_heart_rate, intervals }, respiration_rate: { avg_respiration_rate, intervals }, sleep_stage_timeline: { intervals: sleep_stage_intervals }, snoring: { episodes, total_minutes, episode_details }, restless: { episodes, total_minutes, episode_details }, };

App shows the breakdown on the sleep detail screen sleep detail screen

The API response carries sleep_stage_timeline.intervals — an array of {start, end, stage} objects. The app renders these as the sleep stage breakdown chart, showing exactly what the bed sensor reported.

App wording: "sleep stages as reported by the bed sensor." The app displays exactly what the device reports — no derived sleep score, no percentage-based assessment. The breakdown shows light, deep, REM, and awake durations directly from the glk_sleep_stage field.
